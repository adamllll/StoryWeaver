# 织梦者项目重构计划：AI驱动的互动式小说生成游戏平台

> **核心定位**：从"AI辅助创作工具"转变为"AI驱动的互动式小说生成游戏平台"
> **核心理念**：玩家即作者，主角即玩家
> **开发周期**：2周+
> **技术约束**：2核2G服务器，轻量级架构
> **计划版本**：v1.0
> **创建时间**：2025-12-24
> **预计完成**：2周后（2026-01-07）

---

## 📋 核心转变

| 维度 | 原设计 | 新设计 |
|------|--------|--------|
| **产品定位** | AI辅助创作工具 | 互动式小说生成游戏 |
| **用户角色** | 作者（创作者） | 玩家（探险者） |
| **内容来源** | 作者编写 + AI辅助 | 完全由AI生成 |
| **交互方式** | 编辑器 + 章节管理 | 选择 + 判定 + 状态管理 |
| **最终产物** | 待发布的小说 | 可导出的完整小说 |
| **社交功能** | 无 | 故事分叉系统 ⭐ |

## 🎯 用户旅程

```
1. 开始冒险
   ├─ 选择类型（玄幻/言情/科幻等）
   ├─ 输入关键词（如"修仙"、"复仇"）
   ├─ 设定主角（姓名/性别/性格）
   └─ 或完全随机

2. AI生成故事开局
   ├─ 故事背景（200-300字）
   ├─ 初始场景（500-800字）
   └─ 3-4个开局方向选项

3. 玩家选择 → 判定系统
   ├─ 显示成功率、风险、潜在收益
   ├─ 投骰判定（D100）
   └─ 成功/失败

4. AI生成故事节点
   ├─ 800-1500字的剧情内容
   ├─ 更新玩家状态（生命值/灵力/物品）
   └─ 结尾提供2-4个新选项

5. 循环3-4，直到：
   ├─ 玩家主动结束
   ├─ 达到某个结局
   └─ 生命值归零（Game Over）

6. 冒险结束
   ├─ 整理成完整小说
   ├─ 在线阅读（章节模式）
   ├─ 导出TXT/PDF
   ├─ 分享链接
   └─ 显示分支树可视化
```

## 🏗️ 架构设计

### 数据库模型

#### Adventure（冒险）
```python
class Adventure(Base):
    __tablename__ = "adventures"

    id = Column(Integer, primary_key=True)
    player_id = Column(Integer, ForeignKey("users.id"), nullable=False)

    # 分叉相关
    parent_adventure_id = Column(Integer, ForeignKey("adventures.id"))
    fork_from_node_id = Column(Integer, ForeignKey("story_nodes.id"))

    # 初始设定
    title = Column(String(200), nullable=False)
    category = Column(String(50), nullable=False)  # 玄幻/言情/科幻
    keywords = Column(JSON, nullable=False)
    protagonist_name = Column(String(100), nullable=False)
    protagonist_gender = Column(String(20), nullable=False)
    protagonist_personality = Column(String(200))

    # 当前状态
    current_node_id = Column(Integer, ForeignKey("story_nodes.id"))
    player_state = Column(JSON, nullable=False)

    # 游戏状态
    is_finished = Column(Boolean, default=False)
    final_ending = Column(String(50))  # "happy", "tragic", "game_over"

    # 统计信息
    total_nodes = Column(Integer, default=0)
    total_choices = Column(Integer, default=0)
    total_words = Column(Integer, default=0)

    created_at = Column(DateTime, default=datetime.utcnow)
    finished_at = Column(DateTime)
```

#### StoryNode（故事节点）
```python
class StoryNode(Base):
    __tablename__ = "story_nodes"

    id = Column(Integer, primary_key=True)
    adventure_id = Column(Integer, ForeignKey("adventures.id"), nullable=False)
    parent_node_id = Column(Integer, ForeignKey("story_nodes.id"))

    chapter_num = Column(Integer, nullable=False)
    content = Column(Text, nullable=False)  # AI生成的800-1500字故事

    # 状态快照（方便分叉时恢复）
    state_before = Column(JSON, nullable=False)
    state_after = Column(JSON, nullable=False)

    # 生成的选项（JSON数组）
    choices = Column(JSON, nullable=False)

    created_at = Column(DateTime, default=datetime.utcnow)
```

#### PlayerChoice（玩家选择历史）
```python
class PlayerChoice(Base):
    __tablename__ = "player_choices"

    id = Column(Integer, primary_key=True)
    adventure_id = Column(Integer, ForeignKey("adventures.id"), nullable=False)
    story_node_id = Column(Integer, ForeignKey("story_nodes.id"), nullable=False)

    choice_index = Column(Integer, nullable=False)
    choice_text = Column(String(500), nullable=False)

    # 判定结果
    target_success_rate = Column(Float, nullable=False)
    roll_value = Column(Integer, nullable=False)  # 1-100
    success = Column(Boolean, nullable=False)

    # 状态变化
    state_delta = Column(JSON)  # {"生命值": -20, "灵力": -30}

    timestamp = Column(DateTime, default=datetime.utcnow)
```

#### AIConversation（AI对话历史）
```python
class AIConversation(Base):
    __tablename__ = "ai_conversations"

    id = Column(Integer, primary_key=True)
    adventure_id = Column(Integer, ForeignKey("adventures.id"))
    user_id = Column(Integer, ForeignKey("users.id"), nullable=False)

    # 对话内容（JSON数组）
    messages = Column(JSON, nullable=False)

    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
```

### 核心API设计

#### 冒险管理API
```
POST   /api/adventures              # 创建新冒险
GET    /api/adventures/{id}         # 获取冒险详情
GET    /api/adventures/{id}/nodes   # 获取所有节点
POST   /api/adventures/{id}/fork    # 从某个冒险分叉
GET    /api/adventures/{id}/export  # 导出为完整小说
```

#### 游戏核心API
```
POST   /api/adventures/{id}/choose  # 玩家做出选择
POST   /api/adventures/{id}/finish  # 主动结束冒险
```

#### AI生成API（内部使用）
```
POST   /api/ai/generate-opening     # 生成开局
POST   /api/ai/generate-story-node  # 生成故事节点
```

#### 聊天记录API
```
PUT    /api/conversations/{adventure_id}  # 保存/更新对话
GET    /api/conversations/{adventure_id}  # 获取对话
```

## ⚠️ 风险与应对

### 风险1：AI生成质量不稳定
**应对**：
1. 提示词设计要足够详细，包含示例
2. 添加生成质量检查（字数、格式）
3. 允许玩家"重新生成"当前节点
4. 记录失败案例，持续优化提示词

### 风险2：2核2G服务器性能瓶颈
**应对**：
1. 限制同时进行的游戏数量（最多5个并发）
2. 使用Redis缓存常见场景的AI响应
3. AI调用失败时提供友好提示
4. 考虑使用更便宜的模型（GPT-3.5）

### 风险3：状态管理复杂度
**应对**：
1. 简化状态结构（只保留核心属性）
2. 使用JSON Schema验证状态格式
3. 每个节点保存状态快照（方便回溯）
4. 编写充分的单元测试

### 风险4：2周时间不够
**应对**：
1. 严格遵循P0优先级
2. P1功能可以延后（先上线MVP）
3. 复用现有UI组件和AI服务
4. 简化动画效果（先实现功能）

## ✅ 验收标准

### MVP完成标准

一个完整的游戏流程：
1. 用户创建新冒险（选类型+关键词+主角）
2. AI生成开局（背景+场景+选项）
3. 玩家选择 → 判定 → AI生成后续
4. 重复3，持续5-10章
5. 玩家主动结束或Game Over
6. 生成完整小说并可导出TXT
7. 可以在线阅读（章节模式）

### 质量标准

- AI生成内容连贯、有文学性
- 判定系统公平（成功率符合设定）
- 状态更新正确（生命值、物品等）
- 界面流畅（动画自然）
- 无阻塞性bug
